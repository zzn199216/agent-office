# Agent 办公室 · Agent Office

把你选定的 agents 接入同一间办公室，在文字群聊和办公室画面之间切换。成员以独立身份徽章和完整角色形象入座，实际消息显示为办公室里的对话。角色可以是品牌吉祥物、机器人、动物或用户自己的形象，也能通过同名代理参与 Grok 原生群聊。

办公室采用原创像素风格，连续墙体沿上边缘铺开，左上方为入口。背景自动填满办公室区域，工位和角色保持自然比例，网格随成员增加向右、向下扩展；更多工位可以滚动查看。窗口大小或右侧面板变化时自动重排，普通刷新保留浏览位置。输入栏按需浮动展开，新成员沿走道从门口进入；刷新或重新打开画面不会让旧成员反复进门。默认角色和头像为项目原创像素素材，同模型成员以饰品配色区分；自定义形象优先。素材清单见 [AVATAR_SOURCES.json](web/assets/office/AVATAR_SOURCES.json)。

英文名采用 **Agent Office**，完整描述为 **Agent Office Local**。这是 AgentRoom 的后续版本，原有房间、成员、连接及 MCP/CLI 接口继续兼容。Windows x64 本地预览版 **0.15.0-preview.5**，协调与持久状态留在电脑里，无需购买服务器。模型使用各工具原有服务；订阅和 API 用量按对应服务计费。

0.15.0-preview.5 修复提醒跳转、启动确认迟到时的人工等待超时和无会话请求不回应。新增隔离 CLI 自检、只读待办诊断，以及一条命令构建验收和固定提交的无界面发布队列。构建、验收及隐藏任务的使用方法见 [本机发布与诊断](docs/RELEASE.md)。

0.15.0-preview.2 已在 Qwen Windows 1.0.3、豆包 Windows 2.32.4 上验收原生自动聊天。首次开启本机连接后点「连接本人对话」，AO 保存独立人物会话、自动派发并回写真实回答；换房间或重启后复用原对话。豆包原生 MCP 工具调用与 Grok 原生收发仍待独立验收，详见 [原生桌面对话](docs/NATIVE_DESKTOP.md)。

0.15.0-preview.4 收紧 preview.3 的几处细节：被拒操作的记录只在任务未结束时提示「需要确认」，24 小时后自动清除；「本会话允许」按钮说明其作用范围；秘书引导在你切到文字视图或开始输入时不再自动跳转，接入其他成员不会改写你选好的收件人。

0.15.0-preview.3 统一成员操作规则：日常已授权操作自动继续，需要确认时出现在成员最新对话里；秘书接入成功后进入办公室。权限实现与各客户端能力边界见 [成员操作与确认](docs/OPERATION_POLICY.md)。

0.14.15 按人物生成两份最小 MCP JSON（STDIO / Streamable HTTP），填好程序路径、参数与本机地址，无需任何其他 MCP。安装说明缩短为读取模板、保留配置合并、启用并实际验证。

0.14.14 成员接入页新增「复制 AI 安装说明」，把客户端检查、配置合并和当前对话的工具验证交给有本机配置能力的安装 Agent；保留已有连接、成员凭据和房间权限。接口测试、对话加载工具、消息回写与自动接手分别验收；Qwen Chat 与豆包的后台自动接管仍未实现。详见 [安装委托说明](docs/AGENT_INSTALLATION.md)。

0.14.13 将 HTTP 收件箱改为一段完整 JSON，保留消息和当前连接信息，减少原生客户端对多段文本的兼容风险；Qwen 实际收信已有证据，收信后自动续答仍需验收。保存 HTTP MCP 会话和本机服务端口，后台重启后沿用原地址、成员凭据与会话。不指定 room_id 的收件箱查询跨该成员所有已加入房间，并明确返回当前房间信息。即使退出所有房间，人物连接仍有效，只返回空会话；房间权限在具体消息操作时核验。常用历史与发消息工具默认定位当前会话，无需用户给出房间 ID。接入页新增一次性的连接人物说明，Qwen 明确选择 StreamableHTTP。旧版未保存的会话首次升级可能需重新连接一次；第三方客户端自身保留失败状态仍须原生核验。

0.14.11 补齐删除房间后的连接恢复：已运行的 stdio MCP 每次调用读取凭据当前所在房间；同一成员的多个既有地址都能恢复，查看接入说明沿用原入口文件和凭据。入座、离座与凭据迁移一起提交或回滚，手动撤销有明确标记。0.14.10 的成员凭据迁移与历史恢复继续保留。

0.14.9 让桌面客户端一次接入、所有房间通用：Qwen、豆包、Claude 桌面等手动导入的配置不再绑定单个房间，新房间无需重新导入；连接弹窗按客户端只给它能用的方式（Qwen 使用本机 HTTP MCP，并提醒不要用云端代码解释器）。已接通的同一客户端再次接入时沿用原身份，失败的旧成员可一键清理；扫描能识别装在其他磁盘的 Qwen；接入卡片显示用时，需要确认的步骤直接在卡片上处理；默认进入办公室画面。

0.14.8 的 Codex 接入通过专属后台会话直接调用本机 MCP 握手工具，无需模型生成一次回答；真实验证后进入办公室，业务消息的模型等待另行显示。独立数据目录实测首次约 3.7 秒，已有会话重接约 57 毫秒，接入不产生模型轮次。后台模型采用 HTTP 通信，跳过 WebSocket 超时回退；保留原有账号与自定义服务路由。

删除弹窗先列出接入中、排队、运行、待确认与结果待核对的任务。用户确认后停止本房间的本机工作、取消待办并删除房间，其他房间与共享账号保留；已经送达外部窗口的任务无法保证撤回，原始执行记录保留供核对。确认前新增的任务会刷新清单，要求重新确认。

首次接通一位可后台回答的秘书：一次配置一位，真实握手成功后自动进入办公室，未接通的尝试不占工位。Claude 中转使用已保存的本机 API 配置，配置按钮直接打开文件；占位密钥和服务拒绝会明确提示，保存后继续接入无需重复填写。聊天支持选择、粘贴、拖入和预览图片，Codex、Claude Code 接收实际图像；原生桌面对话暂不支持图片派发。

登记在 UNC 共享目录的项目，Claude Code 会寻找已存在的映射盘符，核对两个路径对应完全相同的目录后使用；不会改动项目登记路径或另建项目。

## 使用

直接打开本地 release/AgentOffice-0.15.0-preview.4-windows-x64/OPEN_TEST.cmd。保持 desktop 文件夹与 EXE 一起使用；无需 Node/Python 或管理员权限。窗口使用微软 WebView2 Runtime，缺少时会给出安装入口。升级时关闭旧窗口并打开新版；新版会在旧后台空闲时自动更新，工作进行中会保留任务并提示稍后更新；原数据目录与已保存记录继续保留。MCP 客户端占用旧 EXE 时，新版使用独立的本机程序副本，不要求关闭这些客户端。

0.14.13 包含房间管理、可恢复归档、像素办公室、同模型配色、Markdown 聊天和输入体验改进。代码中的星号、链接语法等保留原文；Enter 发送，Shift + Enter 换行，中文输入法确认候选时不会发送。测试时可在外观页切换“饰品颜色”，查看两个同模型成员的区别，并核对聊天代码、办公室与离线记录。

聊天会显示成员等待接手、思考和需要确认的状态；对应答复到达后提示消失。收件人按房间记住，消息开头手打完整 `@成员名` 可指定收件人，选择列表支持方向键、Enter 和 Tab。秘书接通前可以先写目标；未保存的 Codex 路径也会保留。Claude Code 后台继续使用受限权限，并读取用户配置中的 API 凭据与模型环境设置，兼容已配置的中转服务。

在窗口中点击 **启动服务**，即可进入群聊和成员管理。服务已有运行时直接复用；关闭窗口后服务继续运行。点击 **停止服务** 才暂停本机消息处理，已有房间和记录保留，服务停止时仍可在窗口查看保存的群聊。已授权成员之后再次进入可按需重新启动同一实例。

空办公室先显示秘书教程：接入并选择一位 AI，交代目标，再和它一起梳理任务逻辑与成员分工。选择秘书不会派任务，点击“让秘书开始”才发送真实委托。已有办公室可从“秘书”入口指定或更换；接入其他 AI 仍由用户点选。详见 [秘书教程](docs/SECRETARY_GUIDE.md)。

**协作** 面板保存目标、各窗口的信息卡、派工和会议。秘书根据具体成员的能力与资料安排任务，成员交付后由秘书验收；遇到缺资料先登记阻塞，避免窗口互相等待。会议收集独立报告、按需定向澄清，生成带版本的共同简报，各窗口确认已读。可以手动开会，也可以按小时设置例会；只有活跃目标出现变化才发起，休眠后最多补一次。详见 [团队协作指南](docs/TEAM_COLLABORATION.md)。

桌面窗口按当前屏幕工作区与 DPI 自然居中，记住用户调整的尺寸和位置。办公室自动适应可用的矩形区域；成员较多时滚动浏览，工位、名称和气泡保持可读。

聊天占据窗口主要空间。顶部切换 **文字 / 办公室**；右侧按需展开成员、资料、连接、外观和场景面板，关闭后把空间还给聊天。两种视图共用同一房间、同一消息和输入框，办公室画面也可直接选择成员发送委托。角色动作由保存的真实消息和处理状态驱动，空闲时只显示轻微待机动画。成员离线、心跳过期或本机服务关闭时保留空工位，成员身份与历史消息仍在，不用角色动画冒充在线工作。

在 **外观** 页选择成员，调整完整角色、头像、大小及办公桌／懒人沙发。在 **场景** 页调整布局、背景、墙地颜色、窗户、绿植和时钟，也可分别上传家具素材。自动昼夜按系统或指定时区切换，夜晚有柔和室内光，办公室时钟显示真实日期与时间。配置保存在本机，停止服务后仍能查看。[外观与场景说明](docs/OFFICE_APPEARANCE.md)介绍可替换项和动画的含义。

选择项目，点击 **扫描本机 agents**，再点目标成员旁的 **一键接入**。程序只为这个成员准备通信、启动受支持的协作后端，并检查真实握手。未安装但可安装的后台入口显示“安装并接入”；首次账号配置或桌面 MCP 启用会显示明确的下一步。

本机通信接通后，复制 Grok 加群说明交给现有 Bot。它使用自己的原生工具，将这位成员的同名代理加入你指定的群。更新私有技能 **/AgentRoom** 后，也可以直接让它“扫描本机 agents”或“把 Codex 加入这个群”。

扫描只在你要求时执行，接入只处理你指定的成员；安装、启动和新进程出现都不会自动扫描或拉人。

接入列表中的 **Grok Bot · 本人窗口桥接** 会复用本房间已有的 Grok 桥接成员与长期入口。点击“复制本人接入说明”，在选定的已有 Bot 窗口用获授权的 Windows 本机工具执行 `enter`；真实握手后显示 `ready_mailbox`。此流程不安装 MCP 或 Grok CLI，也不自动改名、新建原生 Bot 或加群。独立的 **Grok Build CLI** 仍标为暂不支持，不替代 Grok Bot 窗口。

左侧聊天室旁的 **⋯** 打开管理菜单，可归档、恢复或删除房间。归档保留历史与已有协作；删除需要确认并列出本房间工作。删除只作用于所选本机聊天室，成员连接转到仍在的房间；没有房间时暂停，重新入座后恢复。其他聊天室、共享账号及 Grok 原生群保留。[删除说明](docs/USER_GUIDE.md#归档与删除聊天室)

| 入口 | 日常协作 |
| --- | --- |
| Codex、Claude Code、Qwen Code、Gemini CLI | 专用后台协作会话，可处理群里的委托。账号配置和实际握手须完成；不接管已有桌面或网页对话。 |
| Qwen、豆包桌面 | 已核对 Windows 版本可通过「连接本人对话」自动派发并回写回答，复用本人账号与原生会话；首次需开启本机连接。MCP 工具分别配置与验收。 |
| Claude 桌面 | 桌面 MCP 信箱，由本人窗口领取并回复；不能后台唤醒。 |
| Grok Bot · 本人窗口桥接 | 复制本房间的本人命令说明，在已有 Bot 窗口实际执行长期入口；接通后由本人处理消息，不自动唤醒或修改原生群。 |
| OpenCode、Cherry Studio、Cline、Roo Code | 准备对应官方格式的本机 MCP JSON；本人客户端导入、启用及实际握手后，接入消息信箱。 |
| 其他客户端 | 使用通用 MCP 接入或查看具体接口要求；发现进程不会冒充通信接通。 |

Claude Code 需要含 Code 的套餐或 API。Qwen Code 与 Qwen 桌面账号不同，当前须首次配置 API、Token 计划或自定义提供商，不能复用桌面登录。Gemini CLI 使用自己的 Google 登录、API 或 Vertex 认证；本轮适配最低版本 0.63.0。点击“安装并接入”才安装官方包及独立 Node 到本机实例目录，校验完整性并保留系统 PATH、全局 npm 与现有账号。[Gemini 适配依据](docs/GEMINI_CLI_RESEARCH.md)记录协议与安装来源。本轮没有调用真实 Gemini 模型；安装或认证配置存在不替代实际问答和 MCP 握手。

Qwen、豆包主流程使用「连接本人对话」；MCP 保留高级兼容入口，豆包按名称、HTTP 与本机 URL 逐项填写，不把材料 JSON 当作原生自动导入接口。OpenCode、Cherry Studio、Cline、Roo Code 目前只准备导入材料，不猜测或覆盖原生配置；即使接入成功，也不会后台唤醒这些既有窗口。详见[豆包接入指南](docs/DOUBAO_CONNECTOR_GUIDE.md)和[其他客户端合同](docs/ADDITIONAL_AGENTS_RESEARCH.md)。

右侧 **连接 → 连接诊断** 只读检查所选房间、真实成员和长期入口，可以核对旧说明里的成员标识。它不会扫描、刷新心跳或重新发问。Grok 注册的 Windows 电脑、原生群工具与本机服务、Webhook 通知是独立链路；宿主状态须在 Grok 内核对。旧成员不存在时重选本房间成员，打开它的现有恢复或接入说明，不创建替代房间。[连接排查](docs/GROK_CONNECTION_TROUBLESHOOTING.md)

## 开发

Codex 后台协作使用独立会话目录，完整上下文保留在 AgentRoom，个人 Codex 页面保持安静。需要查看时使用“查看工作记录”，或让助手通过 `work-record` 命令导出已有记录并在当前页面打开；查看不调用模型、不重跑任务。详见[后台协作与桌面信箱](docs/USER_GUIDE.md#后台协作与桌面信箱)。

Node 22.13+；运行服务无第三方 npm 依赖。Windows 打包使用 esbuild/postject，并编译 WinForms/WebView2 窗口宿主。服务开发仍可单独用浏览器查看；UNC 路径可直接运行下列 Node 命令：

~~~text
npm ci
node scripts/check.cjs
node --test tests/*.test.cjs
node src/main.cjs start --open
node scripts/build.cjs
~~~

这是未签名的本地预览包，尚未公开发布。
