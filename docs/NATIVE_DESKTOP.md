# Agent Office 原生桌面对话

0.15.0 preview 的「连接本人对话」为办公室同事保存独立的原生会话。模型使用该客户端本人的账号与配置；换办公室房间或重启 AO 后继续沿用同一人物连接。列表中的 Qwen 桌面、Qwen Code，以及其他客户端各自保留独立身份。

打开要接入的客户端，在 AO 接入页点选它，再点击「连接本人对话」。正在运行的客户端仍排在选择器前面。首次连接会核对本机接口和本人会话；发送一条实际消息后，AO 再核对原问题对应的最终回答并回写房间。

接入页分别显示两项证据：

| 显示项 | 成功所需证据 |
| --- | --- |
| 原生会话已加载 | 已识别对应客户端，核对版本和接口，加载这位同事的实际会话 |
| 实际回复已核对 | 原问题的真实用户消息、对应的原生执行终态和完整回答均能关联 |

扫描到应用、保存 MCP 配置、接口自测成功或发送请求被接收，都不会单独显示「实际回复已核对」。有未确认的发送结果时保留原消息引用，继续核对原结果。

截至 2026-10-15，本次 preview 与后续源码核查的实际结果为：

| 客户端 | 当前结果 | 适配版本 |

| 豆包桌面 | 原生 SDK 连续两次真实回复；生产队列通过连续两条、删测试房间后同对话收发、AO 重启同对话续接四轮，打包程序另通过同一对话两轮。原问题服务器 ID 与最终回答父链均匹配，当前聊天和富文本草稿指纹保持一致 | Windows 2.32.4；native stable runtime |
| Grok Bot | 已核对安装包原生方法与版本指纹，真实端点收发尚待验收；本次自动调试启动受工具策略拦截，未执行 | 安装版本 0.70.2 |

Qwen 和豆包的原生自动聊天已通过当前版本验收；客户端升级后仍须核对接口指纹。豆包原生 MCP 连接器注册和模型工具调用是另一项能力，目前未完成验收；本次真实原生连接器列表为空，没有自动改写配置。Grok 的接入按钮会核对已有本机连接，原生收发仍待真实端点验收。

Qwen 已另行核对 rooms/history 的真实模型工具调用与续答。连续读取测试也观察到它有时跳过指定工具并编造答案；当时工具列表和消息链完整，原生正常结束。AO 每次派发会提供本条消息之前的限量当前房间记录，减少长期对话对旧房间记忆的依赖。回答正确、上下文更新与真实工具读取分别验证，不能据此保证模型每次遵循工具指令。

追加当前房间上下文实测的第一轮正确返回随机校验值；随后 Qwen 原生明确返回 `quota_limit`（服务访问量较大）。AO 会显示客户端限流原因并保留失败记录，旧请求不会自动重发。最终包在这次失败及后台重启后，仍沿用同一原生对话完成原房间和另一专用房间的新消息，各自回传正确的新校验值。快速后续请求仍可能受云端限流，稍后提交的新请求成功；客户端额度与模型遵循工具指令仍有实际限制。

## 首次开启本机连接

默认本机端口为 Qwen `19245`、豆包 `19246`、Grok Bot `19247`。AO 只接受回环地址上的对应原生客户端。主接入页自动选择端口；「高级：连接诊断与兼容 MCP」用于核对首次配置。

Qwen Windows 1.0.3 的下列启动方式已经实际核对。先保存当前工作，从 Qwen 菜单正常退出，再在 PowerShell 执行；路径使用该客户端已经安装的 EXE：

```powershell
Start-Process -FilePath 'W:\Program Files\Qwen\Qwen.exe' -ArgumentList '--remote-debugging-port=19245','--remote-debugging-address=127.0.0.1' -WindowStyle Hidden
```

重新打开后，回到 AO 点击「连接本人对话」。本机目标列表应包含 `chat.qwen.ai` 的 `webview`；AO 会选择该原生页面并核对前端文件指纹。

原客户端普通启动不一定保留这些连接参数。完全退出客户端后使用上述入口重新打开，再连接即可恢复原人物对话；无需重新导入 MCP 或创建新人物。AO 升级和房间变化均保留连接身份。

豆包 Windows 2.32.4 在用户从托盘完全退出后，以下方式已实际开启本机连接，回环监听归属原安装的豆包进程：

```powershell
Start-Process -FilePath 'W:\ProgramData\Doubao\app\Doubao.exe' -ArgumentList '--remote-debugging-port=19246','--remote-debugging-address=127.0.0.1' -WindowStyle Hidden
```

原生目标为 `doubao-chat/chat`，实际 Webpack runtime 为 `@flow-web/desktop:stable`。已加载的消息模块与 ai-views 扩展版本不同，不能套用扩展模块编号或指纹。AO 准备连接时执行精确核对过的两个原生资源，再核对八项接口源码。正常延迟加载会替换同一 info 模块；两个已安装变体仅变量命名不同，采用固定双指纹允许列表，未知变体仍拒绝。

AO 为每位豆包同事创建独立原生对话，直接派发并观察对应服务器问题及最终回答；基础聊天不要求先安装 MCP 连接器。创建结果不确定时暂停重建，拿到对话 ID 后即保存，连接失败和模型提交失败分别记录。原生聊天已通过真实验收，MCP 工具证据仍独立记录。窗口控制工具此次无法绑定豆包，因此界面视觉与附件草稿未完成验收；已核对当前选中对话及富文本正文草稿指纹。

Grok Bot 0.70.2 的调试启动仍未执行；本次启动被工具策略拦截。后续需在允许的流程中另行验收真实端点。此文档不提供强制结束进程的流程。

## 连接未完成时

接入页保留原始 API 的具体原因，并给出对应的下一步：打开本人客户端、完成一次本机连接设置、选择唯一实例、处理客户端登录或模型额度，或核对变更后的版本接口。状态读取不会重建人物或重发任务。

原有 MCP 和本机命令入口保留在高级兼容区，按需明确复制。原生接入主流程由 AO 管理人物和房间，不需要用户填写房间标识或提供账号凭据。

维护者实现入口为 [desktop-sessions.cjs](../src/desktop-sessions.cjs)、[desktop-transport.cjs](../src/desktop-transport.cjs)、[desktop-qwen.cjs](../src/desktop-qwen.cjs)、[desktop-doubao.cjs](../src/desktop-doubao.cjs) 和 [desktop-grok.cjs](../src/desktop-grok.cjs)。消息执行记录与连接证据分别持久保存；协议、执行器租约、原生会话和实际回复是独立状态。

## 参考实现

- [ACP 会话创建与加载](https://agentclientprotocol.com/protocol/v1/session-setup)：能力协商、独立会话、带本人 MCP 恢复会话。AO 原生适配器参照这些生命周期边界，未宣称消费端实现 ACP。
- [MCP Agent Mail](https://github.com/Dicklesworthstone/mcp_agent_mail)：持久人物、收件箱与可引用的线程；信箱持久化与原生模型唤醒分别验证。
- [doubao-cli](https://github.com/Fullstop000/doubao-cli)：本机原生会话桥接的公开研究参照。该项目针对 macOS；本次 Windows 豆包适配依据已安装 2.32.4 的实际接口独立核对，并完成上述真实自动聊天验收。MCP 工具调用另行验收。
