# 开发交接

本项目目前处于本地开发阶段。以源码、测试和 Git 提交为准；开发入口及构建命令见根目录 README。生成包、依赖缓存、日志、截图和临时测试数据不属于源码，不应提交。历史设计稿、阶段报告和旧交接记录可从 Git 历史查阅。

## 目录与责任

- `src/`：本地服务、持久信箱、MCP、成员权限和客户端适配器。
- `web/`：聊天、办公室、接入流程及本地运行资产。像素资产定义和导出脚本均须保留。
- `desktop/`：Windows WebView 宿主、窗口与服务生命周期。
- `integrations/`：提供给外部客户端的协作说明和工具合同。
- `scripts/`：构建、打包及隔离验证。
- `tests/`：单元与集成回归，包含假客户端和原生事件夹具；不能当作构建垃圾删除。
- `docs/`：当前协议、架构、接入和验证说明。其中部分文件由构建脚本直接随包分发。

## 当前连接与生命周期约束

软件打开时启动本地服务，关闭时停止本窗口拥有的服务；最小化保留后台工作，暂停前端定时器、事件流和动画，恢复后读取最新状态。宿主会尝试挂起隐藏的 WebView。

`src/desktop-lifecycle.cjs` 保存明确的打开/关闭意图。关闭操作核对 activation、实例和后台进程身份；旧窗口不能停止后来接管的服务。MCP 的后台启动路径不能绕过已关闭状态，只有明确重新打开软件才产生新 activation。

MCP 连接跟随人物，工具按当前成员座位核对房间权限。删房间、新建房间或版本更新不应要求重新导入同一人物的 MCP。用户明确撤销的凭据不能自行恢复。已提交但结果不确定的外部任务不能自动重发。

Codex 后台会话使用原生 `shared-cache` 认证方式，保留原环境的凭据存储、模型与提供方配置。AO 不复制或覆盖个人认证；人物使用独立工作线程及确定性 MCP 名称。缓存共享仍可能遇到提供方的认证或刷新错误，不得用测试夹具通过宣称真实账号永远不会失效。

接入状态必须区分：发现应用、写入配置、协议握手、绑定原生对话、真实消息往返。进程存在、心跳、房间座位或接口自测都不足以单独证明自动聊天成功。可用连接先复用；必须人工完成的步骤应给出明确、简短的下一步。

聊天按真实消息 seq 排序。接入进度只合并到同一房间、同一原请求和同一收件成员的真实回复；未回复时在原请求内展示紧凑进度。合成进度不伪造独立人物消息或时间。

## 验证

基础检查不启动真实模型：

```powershell
npm ci
npm run check
node scripts/build-desktop.cjs
node --test --test-concurrency=4 tests/*.test.cjs
git diff --check
```

全新 checkout 须先构建 Windows 桌面依赖，避免 WebView2 测试因缺少 SDK 而跳过。打包后的专项脚本均应使用隔离数据、假客户端和明确的可执行文件路径：

```powershell
node scripts/validate-desktop-lifecycle.cjs <AgentOffice.exe>
node scripts/validate-startup-recovery.cjs <AgentOffice.exe>
node scripts/validate-mcp-continuity.cjs <AgentOffice.exe> [previous-AgentOffice.exe]
node scripts/validate-page-activity.cjs
node scripts/validate-connection-assist-ui.cjs
```

验证结果必须标明使用的是源码、打包程序、假客户端还是实际客户端，以及是否真的收到模型最终回复。隔离浏览器和 C# 夹具测试不等于用户客户端已接通。真实窗口操作须先满足用户对电脑空闲的要求；不要触碰个人账号或现有聊天来做无关验证。

开发测试数据可以重建，不承担尚未发布版本的历史数据兼容义务；这不意味着应把运行数据、账号或凭据写进 Git。当前开发提交和必要连接配置应分别管理，避免为每次修改保存整套旧包。

## 接入统计口径（从 preview.21 开始采集）

`node src/main.cjs stats --since-version 0.15.0-preview.21 --json [--data-dir DATA_DIR]` 直接以只读事务打开 SQLite，不启动服务，不输出成员身份、消息正文、文件路径或凭据。重复读取同一个未变化的库输出一致。版本筛选含指定版本；无版本的历史记录只列数量，不假装成可追溯尝试，也不回填成功。

首次接入按（房间，客户端/provider）第一次实际发起；其后实际发起为重试。重复点击、状态查询、等待原请求不新增尝试；显式失败重试会记录新的不可变开始时间和软件版本，即使沿用原 run_id。四类结果按房间/客户端聚合：首次接通、重试后接通、用户放弃、仍在等待。失败但尚未放弃属于等待处理，另列失败码排名；被重试替代的尝试保留。MCP/协议接通与本次自动回复验证分别计数；握手不等于自动回复。按 UTC 周一分周，耗时中位数单位毫秒，只有成功的尝试进入接通耗时。没有可用样本时中位数为 null。

消息统计只包含指定版本之后实际写入、由用户发给成员的普通消息；排除接入验证问题，回复必须是同一请求、同一收件成员的真实 reply。回复率分母包含未回复的请求，耗时只计首条关联回复。房间创建/删除分别按操作发生时版本统计；历史删库/清理不构成新接通。单机开发数据仍不代表真实用户总体成功率。

### 1c / 1d：认领、分工与战绩（preview.24）

「认领与成员分工」在房间选项中独立开启。复杂任务的同一次分派可给两轮建议，保存为现有 meeting 记录，明确标为秘书预测；每位成员只有用户点「请这位参与认领」才产生真实的两轮轻量调用。第一轮做法/缺口、第二轮主做或协助，系统附实际适配器能力；每人每轮一次，90 秒总截止，重复点击不会重调。真实意见一致则收敛；分歧由一次独立轻量裁决处理，仍不确定交用户选择，不能循环讨论。候选不含无法自动处理的桌面窗口；它们仍可明确 @并通过原入口工作。

阶段 0、1a/1b、1c/1d、2a、3a、3b、3c、3d、3e 各有独立提交。交付分支 codex/onboarding-progress-compose，开发版入口为本检出的 dev/AgentOffice.exe。最终提交后再运行一次完整门禁，使开发版 manifest 绑定干净提交；结果和截图在忽略目录 output/verify-dev/，Windows CI 执行相同门禁。Y: 原快照分支仍为 dbdc950，工作区干净，旧工作目录和分支未删除。

所有新功能按房间默认关闭，从「房间选项」分别开启。群内讨论不设默认每日上限；不开讨论就不增加分诊/认领调用。待确认的保守选择及实际验收边界：

- 轻量分派目前只对已经核对禁用工具参数的 Codex/Claude 开放；其他自动客户端能按明确规则接任务，不能安全轻量分诊时交用户指定负责人，不偷偷退回完整工作会话。
- 试用是两份只读方案，选用后才继续；模型预测只作秘书建议。实际分派、认领质量与提供商真实费用尚未用个人账号验证，字符数和调用尝试不能换算成实际账单。
- 动画优先级、拥堵停止、最多三位空闲活动和远距离原地互动均选保守做法。新画布使用统一原创动作图；旧模式继续提供原有图片外观设置，新画布暂不把单张自定义图片伪装成完整动作图。
- 个人正式库升级清理、真实 Windows 客户端回复仍属真实试用验收。自动检查全程使用全新隔离数据和适配器夹具；正式库只读 stats 没有当前版本接入样本，不能给出真实成功率。正式升级前需 SQLite 一致性备份，运行中的数据库不能只复制主文件而遗漏 WAL。
