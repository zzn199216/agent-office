# 从 AI 秘书开始

空办公室首先显示三步教程：选择一位 AI 秘书、交代目标、一起组织成员。教程不会自动扫描电脑、安装客户端或调用模型；也可以先收起教程看看办公室，之后从“秘书”入口重新打开。

1. 点击“接入一位 AI”，明确点击扫描并选择目标，使用现有接入流程。已经在办公室里的成员可以直接指定为秘书，已有房间也可在右侧成员页更换秘书。
2. 等待真实接入。待接通角色只能先保存，不能开始委托；需要账号登录、启用 MCP 或导入配置时，界面会显示对应步骤。
3. 写下办公室目标并点击“让秘书开始”。这会保存一个协作目标，并创建一条实际发给所选秘书的聊天委托。相同成员与目标的首次请求会复用原消息和目标，不因重复点击或重启再次投递。
4. 秘书返回实际回复后，教程才显示“已回应”。通过“查看目标与任务”进入协作面板，查看派工、交付、窗口信息卡和会议；再通过“接入其他 AI”点选成员。

后台可处理的成员和信箱模式分别显示。信箱秘书仍需到自己的窗口领取并回答；指定秘书角色不改变原工具的唤醒能力、账号要求或项目权限。

秘书负责拆解已授权目标、派工、跟进交付和主持会议。成员只能更新自己的窗口卡、任务与报告，不能替别人确认已读。安装或接入其他 AI 仍由用户选择实际目标，秘书角色不赋予控制器、安装或群管理权限，也不会自动拉进 Grok 群。只在用户要求时扫描，不定期扫描或主动拉人。

秘书角色按房间保存，目标草稿相互独立。清除角色不会取消已经投递的任务，原消息仍在文字聊天中。多窗口更换角色时，首次委托校验点击时的成员和角色版本；过期请求会提示重新确认，保留目标草稿。

本机服务停止后仍能查看保存的角色、消息和协作记录，不能更换角色或投递新目标。秘书角色管理 API 为控制器专用的 `GET/POST /api/secretary` 和 `POST /api/secretary/start`。团队工具按当前房间角色校验，每次调用都重新检查；更换秘书立即撤销旧秘书的协调权限。完整流程见 [团队协作指南](TEAM_COLLABORATION.md)。
